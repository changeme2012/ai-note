### 1. [alibaba/open-code-review](https://github.com/alibaba/open-code-review)

- **分类 / 用途：** AI 工程；用确定性规则、文件规则和 LLM Agent 生成行级代码审查意见。
- **增长 / 热度：** [Trending 日榜](https://github.com/trending)采集时约 `+3,231`；仓库约 32.3k Star，仍在活跃推送。
- **适合谁：** 想降低 AI 审查噪声、同时保留规则门禁的研发团队。

- **风险 / 局限：** README 的准确率、F1 和 token 节省是项目方基准；其设计会以部分召回换精确率，必须在自己的历史 PR 上测误报、漏报与成本。[许可证为 Apache-2.0](https://github.com/alibaba/open-code-review/blob/main/LICENSE)。

- **增长 / 热度：** 日榜约 `+1,546`；仓库约 35.1k Star。

## 分类观察

- **AI 工程与安全：** `open-code-review` 和 `security-audit-skill` 都在减少“模型自由发挥”，前者依靠规则提高审查精度，后者依靠覆盖账本和独立验证提高可审计性。
- **Agent Skills：** `ECC` 与 `agent-skills` 的价值不在技能数量，而在能否最小化安装、固定版本、审查 Hook、运行测试并安全卸载。
- **知识与研究 Agent：** `WeKnora` 偏企业知识治理，`OpenResearch` 偏研究任务和算力编排；两者共同难点是权限、成本、远程执行和数据边界。
- **本地生成与推理：** `colibri`、`voicebox`、`YuE` 分别代表大模型存储分层、本地语音和可编辑音乐；“本地”不等于低风险，权重许可、硬件成本和内容权利仍需核查。
- **计算机视觉：** `supervision` 是成熟的工程积木型项目，热度不如新 Agent 爆发，但更适合在 30 分钟内做出可验证结果。

## 30–60 分钟学习路线

1. **10 分钟：准备隔离样例。** 创建一个没有密钥和生产数据的小仓库，加入一个输入校验缺陷、失败测试和预期修复范围。
2. **15 分钟：建立审计基线。** 运行现有测试与静态检查；只读检查 `security-audit-skill` 的技能文件、验证脚本、依赖和输出目录。
3. **20 分钟：受限执行。** 在禁外网、环境变量白名单、CPU/内存限制和独立写目录的容器中运行审计，保存覆盖账本、候选发现和验证结果。
4. **10 分钟：人工复核。** 逐条复现高风险发现，标记真阳性、误报与未验证项，再与 `open-code-review` 的规则式意见比较覆盖和噪声。
