## 分类观察

- **研究与知识库**：`llm_wiki` 偏持续知识维护，`hyperresearch` 偏引用与 Markdown 笔记，`OpenResearch` 偏并行实验执行。三者共同趋势是把中间证据和运行记录留在本地，而不是只保留最终回答。
- **编码 Agent 工程**：`spec-kit`、`superpowers`、`ECC` 都在把 Agent 行为显式化，但侧重点分别是规格、开发方法和 harness。选型时应先确定要解决的是需求漂移、缺陷流程还是运行控制。
- **交互与控制面**：`i-have-adhd` 改善输出契约，`PI-Desktop` 提供桌面权限控制。前者低成本但容易过度压缩，后者能力更强但权限风险更高。
- **可验证视觉产物**：`archify` 延续周榜热度，说明 HTML/SVG、自检和导出链路仍比只生成不可编辑图片更有工程价值。[周榜](https://github.com/trending?since=weekly)

## 30–60 分钟学习路线

1. **10 分钟：定义研究问题。** 选一个窄问题，写明时间范围、允许来源、必须逐条引用的主张和停止条件。
2. **15 分钟：建立可追溯资料夹。** 用 Markdown 为三条来源记录标题、日期、链接、核心主张和可信度，不先写长篇总结。
3. **20 分钟：双 Agent 交叉检查。** 一个 Agent 提炼结论，另一个只寻找反例、过期信息和缺失引用；人工合并差异。
4. **10 分钟：固化验收规则。** 把“来源可访问、引用逐条对应、未知明确标注、成本不超预算”写成检查清单。
